## Runtime requirement: no full catalogue scan
- Logical camera IDs and immutable plane bounds are stored once. 60,000 descriptors are allowed; no texture, render target, per-frame job or GPU resource is created for dormant IDs.
- Offline build a separate spatial BVH over optical plane bounds (and/or conservative portal/zone lists). Query from the primary view frustum; do not iterate all IDs or assume that the player's current zone alone contains all visible planes. Use conservative bounds, include adjacent visible zones, and rebuild/refit on geometry changes.
- Traverse only intersecting nodes, then perform side/projection/occlusion tests on the resulting shortlist. Preserve selected IDs across frames where safe, invalidate on pose, FOV, scene changes, and use hysteresis to avoid flicker. A degenerate BVH can still produce many candidates; instrument node visits and candidates, not only active count.
- Maintain a compact active-ID list and a bounded reusable GPU target pool, separate reflection from refraction and exclude recursive camera activation by default. Only active IDs dispatch render jobs. The number of active cameras is the resource budget, not the size of the global catalogue. The two-camera target is an observed property and a regression test; do not silently discard needed optical planes.
- One shared environment probe for lift glass, cached across frames, update only when needed; original normal/Fresnel/roughness/transmission remain unchanged. Probe approximation must be compared to baseline; six cube faces are not free and are not counted in planar camera statistics.

Implemented now: author override, probe declaration, sparse selected IDs for each authored test view, native regression harness. NOT implemented: production spatial index/query, continuous-camera activation, GPU target pool, actual shared probe rendering, packaging of policy into a new scene release. The offline simulation still enumerates plans intentionally. Add separate 60,000-plan spatial stress test (visited nodes, tested candidates, active IDs, CPU cost and memory) before runtime rollout.

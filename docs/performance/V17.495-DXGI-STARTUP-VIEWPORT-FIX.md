# CSE WARP V17.495 — Correctif démarrage DXGI natif

Capture utilisateur du 15 novembre 2026 (V17.494) : interface noire avec texte
« Scène chargée. Calcul de la première image… ». Le statut DirectX annonce
**100×64** et ~1,5 ms, soit un retour de présentation réussi vers une surface
de taille fantôme, mais aucune image dans la vraie zone 3D.

## Cause identifiée dans le code

La méthode de rendu Windows est mise sur D3D11 index 4 dans `createUi()`
**avant** que le signal `currentIndexChanged` soit connecté. Le sélecteur
`directDisplayBox_` est précoché, mais le `QStackedLayout` reste sur
`canvas_`. Qt ne dimensionne donc pas la fenêtre native masquée, dont la
taille est ensuite bornée artificiellement à 100×64. Le moteur peut ainsi
annoncer un faux rendu correct.

## Correction

- Synchroniser **explicitement** la fenêtre native juste après `createUi()`.
- La synchroniser aussi après le chargement d'une scène.
- Refuser de lancer DirectX/Vulkan natif tant que la fenêtre enfant n'est pas
  visible et à la taille de son conteneur, et reprogrammer un essai après
  l'initialisation des widgets. Retour visible à QImage si le conteneur ne
  devient pas disponible.
- Calculer la résolution sur le **conteneur affiché**, sans le clamp 100×64.
- Garder les six caméras accessibles en haut, mais les raccourcir pour que le
  sélecteur **DX11 / Vulkan** soit visible. Les noms restent accessibles via
  les tooltips et la liste complète dans le panneau.
- Conserver les anciens smokes Qt hors écran sur le rendu QImage.
- Ajouter un test Qt hors écran de la sélection native, de la présence du
  backend Vulkan et du changement de page de viewport.

## Limite de validation

Ce smoke UI sur GitHub Actions valide la logique Qt, **pas la présentation
physique de DXGI ni les FPS sur Intel HD 620**. Une vérification visuelle
et une comparaison A/B à 1366×768 restent indispensables. La scène V17.493
et les textures PBR ne sont pas modifiées.

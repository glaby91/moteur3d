# CSE WARP V17.444 — rendu périphérique multirésolution DX11 (EXPÉRIENCE)

## Périmètre
- Branche séparée depuis V17.443. Code d'origine conservé. Opt-in strict : `M3D_V17_PERIPHERAL_MULTIREZ=1` ; absent/0 = raster classique.
- Pas de reprojection temporelle, pas d'historique, pas de flou post-traitement.
- Deux passes D3D11 : périphérie à 50 % des dimensions (25 % des pixels) ; centre à résolution native, avec découpe rectangulaire extérieure 94 % × 96 % et rejet shader hors de la lentille elliptique.
- Le shader basse résolution évite l'ombrage du disque elliptique central (rayon normalisé inférieur à 0,82). Le passage haute résolution rejette les pixels au-delà d'un rayon de 1,0. Chaque passe a son propre Z-buffer.
- Correction du retour utilisateur après premier test V17.444 (bandes rectangulaires) : **spot de netteté elliptique** centré sur l'axe optique de la caméra, rayon écran normalisé `(uv - 0,5) / (0,47 ; 0,48)`, ~50 % de surface pleinement nette jusqu'à `r=0,84`, transition longue et progressive jusqu'à `r=1,0`. Les pixels de bord restent issus de l'image courante, sans reprojection. Pas de modification de luminosité ou d'éclairage.
- Échantillonnage sRGB dans un espace de mélange linéaire. MSAA natif conservé pour le centre, arrière-plan demi-résolution sans MSAA.
- Retour buffer GPU→CPU conservé pour le comparatif de la version 17.443. Tous les temps GPU rapportés incluent deux passes + composition.

## Essai A/B
```bat
set M3D_V17_PERIPHERAL_MULTIREZ=0
moteur3d_v17_benchmark.exe benchmark-civic\scene.json RESULTATS\REFERENCE --smoke --raster-msaa 1
set M3D_V17_PERIPHERAL_MULTIREZ=1
moteur3d_v17_benchmark.exe benchmark-civic\scene.json RESULTATS\MULTIRES --smoke --raster-msaa 1
```
Comparer **gpuDrawMs**, puis **meanMs** et le rendu visuel : fresque, verrière, lignes d'eau, escaliers, végétation, surfaces transparentes. Ne pas comparer seulement les FPS à partir de rendus de résolutions différentes.

## Critères de décision
- **GO** : diminution ≥15 % du temps GPU médian, même résolution, même caméra, même qualité, mêmes conditions, sans artefacts visibles gênants ni régression de stabilité.
- **NO-GO** : <15 % de gain ou défaut de composition/occlusion. La fonction doit alors rester désactivée et ne pas être proposée comme amélioration acquise.
- Les tests CI avec `M3D_V16_FORCE_WARP=1` vérifient compilation, fonctionnement et comparabilité technique **mais ne représentent pas le GPU Intel HD 620**.
- Sur HD 620, refaire au moins 3 passes successives par mode à résolution native 1366×768, en alternant A/B pour réduire les effets de chauffe et variation de fréquence.
- Ancienne variante rectangulaire : 11,91 % (bassin) / 12,04 % (piscine du soir) de gain GPU sur **WARP logiciel 640×360 uniquement**, tests du 13 novembre 2026. Le nouveau profil elliptique **n'a pas encore de résultat validé** ; ne pas reprendre ces chiffres comme preuve de son gain.

## Limites connues de ce prototype
1. La géométrie est envoyée deux fois ; sur des scènes limitées par triangles/vertex shaders, le gain peut être nul ou négatif.
2. Les transparences et les MSAA différents entre centre et périphérie doivent être inspectés visuellement.
3. C'est un mode *expérimental statique*. L'activation automatique seulement en déplacement n'est pas intégrée : la comparaison vise d'abord la faisabilité et le rendement réel.
4. Ce prototype ne change ni la caméra/FOV ni la géométrie et les matériaux de la piscine.

## Activation
Dans un terminal Windows avant de lancer le moteur ou le banc :
```bat
set M3D_V17_PERIPHERAL_MULTIREZ=1
```
Pour revenir au rendu de référence :
```bat
set M3D_V17_PERIPHERAL_MULTIREZ=0
```

## Correction visuelle — halo de netteté type « phare »
Le masque est **radial et sans aucune frontière rectangulaire**. Le centre du halo reste le point de visée (centre du viewport), même avec FOV FPS plus large. Le centre reste natif. Le couloir de transition 0,84→1,00 du rayon a une interpolation HLSL `smoothstep`, continue avec dérivée nulle aux extrémités. Les transitions doivent être testées sous caméra libre : contours des poutres, vitres, ciel, fresque et eau, en marche et à l'arrêt. Cette correction n'est pas un suivi de regard (aucun eye tracking), ni une vignette de lumière.

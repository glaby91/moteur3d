# CSE WARP V17.496 — GPU native viewport shutdown

GitHub V17.495 run [43769065220](https://github.com/glaby91/moteur3d/actions/runs/43769065220)
*compiled successfully* and printed `V17 NATIVE GUI: PASS, stack=1, vulkan=5`,
but returned a nonzero Windows exit code during shutdown. Therefore the new
Qt offscreen smoke failed even though the native-page activation assertions passed.

Fix: after draining both workers, explicitly release the Vulkan WSI surface,
Vulkan preview context and DXGI swapchain on the **same dedicated render thread**
on which their thread_local devices were created, while the Qt-owned native
Win32 child window is still alive. Only then switch the viewport back to the
QImage canvas and allow Qt's QWidget destructor to tear down its children.

CI now prints the real exit code and requires a zero process exit; it does NOT
replace the test with `_Exit`, which would hide a shutdown defect.

**Separate open issue**: [#70](https://github.com/glaby91/moteur3d/issues/70)
Vulkan material texture array packs 186 material layers into a hard 128 MiB
budget, often selecting 256px base textures. This causes real visual blur and
is NOT solved by the shutdown patch. No PBR texture quality setting is reduced
here; preserving full detail will need a working-set/streaming strategy and
HD620 image comparisons.

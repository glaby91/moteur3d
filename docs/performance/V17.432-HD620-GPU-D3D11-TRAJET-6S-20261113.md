# CSE WARP V17.432 — Référence GPU DirectX11 Intel HD 620 (13 novembre 2026)

## Périmètre

Benchmark **réel sur le Dell utilisateur**, mode **GPU D3D11 Raster matériel** (pilote Intel HD Graphics 620, vendor 0x8086), **pas Microsoft WARP logiciel**, ni ray tracing CPU.

- Scène : V17.430 corrigée, `benchmark-civic/scene-v7-corrections.json` (9 anomalies corrigées, mosaïque originale conservée).
- Secteur : caméra `v8_glazing_raccords` (vitrages, angle le plus lent de la campagne *logicielle* précédente ; pas nécessairement le plus lent sur HD 620).
- Trajet : caméra en translation horizontale de 5,4 m, de x = -30,7 m à -25,3 m ; **6 secondes virtuelles** en **90 images** (caméra y=4,5, z=16).
- Résolution native : **1366×768** ; MSAA **2×** ; textures PBR **2048 px** ; shaders et scène inchangés.
- Archive de mesure transmise : `BENCH-GPU-HD620-20261113-020146.zip`, contenant `frames.csv`, `summary.json`, `frame_000.png`, `frame_045.png`, `frame_089.png`.
- Build du programme de benchmark : branche `feature/v17-432-warp-cpu-memory-loop-261113`; [compilation et smoke test réussis](https://github.com/glaby91/moteur3d/actions/runs/43341001061).

Important : les **66 ms d'attente CPU Map recouvrent largement le travail graphique GPU** ; ne jamais les additionner aux 64 ms de dessin GPU. La charge CPU indiquée est celle du **processus**, pas celle de Windows. Les chiffres DXGI d'occupation mémoire sont **globaux à l'adaptateur** et non spécifiques au processus. Des compteurs peuvent être indisponibles ou bruités sur certains systèmes. Les images ont été calculées sans cadence d'affichage/vsync ; il ne s'agit pas des FPS UI exacts.

## Diagnostic et prochaine étape

1. **Priorité au coût des appels Draw sur la HD 620 (~64,4 ms).** L'hypothèse GPU-bound est fortement appuyée par le taux d'activité GPU et le faible coût de soumission CPU. Cela **n'identifie pas encore** le shader en cause.
2. Profilage ciblé, sans dégradation de rendu : mesurer séparément *vertex / pixel shader, alpha / transparences, overdraw, rasterisation, ombres et accès textures* ; utiliser des variantes instrumentées et la même caméra/résolution/qualité.
3. Poursuivre la comparaison A/B sur 90 images avec compteur GPU timestamp, P50/P95/P99, mémoire et **contrôle image pixel-à-pixel** ou différence quantifiée. Ne retenir que les modifications au gain reproductible et à la fidélité préservée.
4. Ne pas relancer la campagne complète ni les tests AVX2 pour ce problème : **ce benchmark porte exclusivement sur le GPU D3D11 Raster matériel**.
5. L'utilisateur a relevé d'autres incohérences de scène ; **ne pas modifier l'architecture ni la fresque dans ce lot performance**, inventorier ces anomalies séparément lors de la prochaine séance.

## Traçabilité / limites

Les agrégats ci-dessus ont été recalculés et vérifiés à partir du ZIP fourni (90 lignes dans `frames.csv`, `summary.json`), et **non** extrapolés des tests GitHub WARP. Le ZIP original des captures et des traces est conservé dans la conversation, mais **n'est pas incorporé dans ce dépôt par ce commit texte**. Le benchmark de profilage Windows et son workflow de compilation sont déjà présents sur cette branche. Il faudra conserver le ZIP source pour rejouer les analyses fines.

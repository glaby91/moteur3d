# V17.434 — repérer et reproduire une anomalie architecturale

Le diagnostic caméra est conçu pour permettre à un second intervenant de retrouver **le même endroit, la même hauteur et le même angle** dans la scène CSE WARP, sans déduire les coordonnées d'une capture seule.

## Pendant l'exploration

- L'overlay de la vue 3D affiche les coordonnées monde de l'œil **X, Y, Z en mètres**, l'azimut (yaw) en degrés, l'inclinaison (pitch) et le FOV.
- Il se met à jour sur le thread d'interface immédiatement après le déplacement/la rotation, indépendamment du rendu D3D11 asynchrone.
- L'affichage se masque depuis **Affichage → Afficher les coordonnées caméra (HUD)**. La préférence est mémorisée.
- Origine de l'azimut : 0° regarde vers **-Z** ; l'angle positif tourne vers **+X**. L'axe **Y** est vertical.

## Transmettre une anomalie

1. Se placer dans la scène et regarder la zone à corriger.
2. Laisser l'image finir de se calculer si l'on veut capturer la position tout juste choisie.
3. Appuyer sur **Ctrl+Maj+A**, ou choisir *Fichier → Capturer une anomalie*.
4. Transmettre les **deux fichiers** `ANOMALIE_*.png` et `ANOMALIE_*.json`, enregistrés dans le dossier Documents/CSE WARP/Anomalies.

**Important :** le moteur peut afficher temporairement une image en retard sur les mouvements. Pour une capture, la pose stockée sous `camera` correspond toujours à l'**image PNG réellement produite**, issue de la requête de rendu acceptée. `liveCameraAtCapture` documente l'autre état, mais **ne doit pas servir à reproduire ce PNG**.

Le fichier JSON stocke :
- `format: cse-warp-camera-anomaly-v1` ;
- version et révision de l'exécutable ;
- fichier manifeste de scène, titre et chemin du poste d'origine ;
- `camera.eye`, `camera.target`, `camera.fovDeg`, `camera.yawDeg` et `camera.pitchDeg` ;
- nom du PNG, résolution, date et convention de coordonnées.

La capture PNG inclut un encart avec les coordonnées de **sa caméra de rendu**.

## Rejouer exactement le point de vue

1. Ouvrir la même scène (même nom de manifeste et même titre).
2. Cliquer sur **Fichier → Restaurer une caméra d'anomalie**, ou **Ctrl+Maj+O**.
3. Choisir le JSON joint à la capture. Le programme vérifie le format et la validité des coordonnées, du FOV, du regard et de l'identité de scène.
4. L'image est recalculée à la position restaurée. Le mode marche est désactivé à ce moment pour éviter de modifier la hauteur Y par accrochage au sol. On peut ensuite reprendre l'exploration en vol libre.

**Ctrl+Maj+C** copie le JSON de la caméra *actuelle* dans le presse-papiers ; c'est utile pour partager uniquement le point de vue, sans capture.

## À propos

Menu **Aide → À propos de CSE WARP V17.434** : version/build, révision et date de compilation, système, adaptateur DXGI principal (indication, pas une preuve du GPU effectivement sélectionné par toutes les configurations multi-GPU), backend sélectionné, Qt, MSAA, résolution des matériaux et état des options expérimentales Z-prepass / rejet AABB. Un bouton copie ces données.

## Périmètre, qualité et essais

- Cette fonction **ne modifie pas la géométrie, la fresque historique, les textures ni la qualité du rendu**.
- Couverture automatisée : sérialisation/restauration millimétrique des coordonnées de test, FOV, rejet des poses invalides, texte du HUD.
- La campagne Windows compile l'exécutable Qt actuel, vérifie les tests et exécute deux rendus DirectX11 WARP logiciels. Les FPS d'une carte Intel HD620 nécessitent des essais sur le poste utilisateur.
- La branche V17.434 n'est pas fusionnée automatiquement dans `master` ; son PR est conservé en brouillon jusqu'à validation.
